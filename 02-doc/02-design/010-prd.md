| 项 | 内容 |
| --- | --- |
| 工作名 | CourseMap（课程知识时间轴） |
| 版本 | v1.0 |
| 日期 | 2026-09-30 |
| 阶段 | 阶段2 需求设计 |
| 平台 | 纯本地 Web App（Next.js，localhost 运行） |
| 存储 | SQLite + 本地文件系统，无后端部署、无账号、无云同步 |

> **本产品的核心不是"AI 总结视频"，而是：把老师 1～2 小时的口语化教学内容，编译成一份可导航、可复习、可溯源的课程知识地图。** AI 负责读薄，原始课程负责读深。

---

## 1. 背景与产品定位

### 1.1 一句话

将 Whisper 转写的雅思网课纯文本（含时间戳），转化为「全局概览 → 知识点导航 → 带着重点听课 → 带个人思考的时间轴复习」的个人学习导航系统。

### 1.2 为什么做（用户痛点）

- 上了约 80 节雅思网课（听力/口语/阅读/写作，每科 10-20 节，每节 1-2 小时）
- 网课注意力不集中，内容左耳进右耳出
- 已通过 Whisper 将视频转为带时间戳的 JSON 文本，但纯文本阅读效率极低
- 缺乏结构：不知道一节课讲了什么、哪里是重点、老师敲了什么黑板
- 复习时无法快速定位：拖动视频进度条效率低，笔记与视频时间点脱节

### 1.3 核心设计原则

| # | 原则 | 说明 |
| --- | --- | --- |
| 1 | **教师原课 = Source of Truth** | AI 不替代老师，不补充老师没讲过的内容 |
| 2 | **AI = Compiler/Editor** | AI 只做：删除口水话、压缩、合并、分类、重排、建立层级 |
| 3 | **所有 AI 内容可溯源** | 每一句 AI 整理的内容都能追溯到老师的原始 Transcript |
| 4 | **知识树只存知识** | "老师重点""易错点""我的笔记"是知识节点下的叶子，不是知识节点本身 |
| 5 | **AI 负责读薄，原课负责读深** | 用户通过 AI 快速建立认知地图，真正学习仍在老师的讲解中发生 |
| 6 | **宁缺毋滥** | 如果老师没讲清楚或 AI 无法确定来源，标记为 unclear/needs_review，不编造 |

### 1.4 与现有项目的关系

| 项目 | 关系 |
| --- | --- |
| `01-English/` | 同类工具链参考：PDF 词汇笔记 → 思维导图。本项目处理网课转写文本，LLM 结构化提取思路可复用 |
| `20260922-ielts-one/` | 同根项目，同为雅思备考工具。ielts-one 聚焦词汇+阅读的每日闭环（微信小程序），本项目聚焦网课内容的结构化导航。两者互补不重叠 |

## 2. 用户画像与场景

### 2.1 用户画像（MVP 阶段：单人自用）

| 维度 | 描述 |
| --- | --- |
| 身份 | 备考雅思的成年人，本人即唯一用户 |
| 目标 | 提高网课学习效率，把 80 节课真正学进去 |
| 技术水平 | 有技术背景，AI coding 为主，能配合调试 |
| 已有资产 | 80 节网课视频 + Whisper 转写的 TXT/JSON（含时间戳） |
| 使用设备 | 主要为电脑（需要看视频 + 看文本 + 记笔记） |

### 2.2 核心场景（三阶段闭环）

```text
【阶段一 · 预习】2-5 分钟
  AI 已生成课程知识地图
  → 快速浏览：这节课老师讲了哪些知识点
  → 看到老师敲黑板的地方
  → 建立认知地图，知道注意力该投向哪里

【阶段二 · 学习】正常看视频
  边看视频边学习
  → 产生思考时，随时点击"记录我的想法"
  → 笔记自动绑定当前视频时间
  → AI 异步将笔记归类到对应知识节点
  → 老师敲黑板的地方有标记提醒

【阶段三 · 复习】1-2 分钟
  打开课程知识时间轴
  → 快速扫完整节课的知识结构
  → 看到老师重点 + 自己的思考
  → 想深入时，点击直接跳转到视频对应时间点
  → 不再需要重新看完整课程
```

### 2.3 场景约束

- 纯本地运行，不依赖网络（LLM API 调用除外）
- 视频在本地硬盘，通过本地 server 读取播放
- 无登录、无账号、无数据上报
- 任意步骤可中断可恢复，状态持久化

## 3. 核心用户旅程（逐屏）

### 屏 0 · 课程列表页 `/courses`

**目的**：看到所有已导入的课程，选择进入哪一节。

**内容**：
1. 课程卡片列表：课程标题、时长、知识点数量、笔记数量
2. 每门课程的状态：未解析 / 解析中 / 已就绪
3. 导入按钮：导入新的 Whisper JSON + 关联视频文件

**交互规则**：
- 点击课程卡片 → 进入该课程的预习页
- 解析中的课程显示进度条（normalizing / chunking / extracting / merging / summarizing / validating）
- 解析失败的课程标红，可重试

---

### 屏 1 · 课程预习页 `/course/:id/preview`

**目的**：2-5 分钟内建立整节课的认知地图。

**布局**：
- 上方：课程标题、总时长、AI 生成的一句话概述
- 中间：课程知识地图（可展开/折叠的多级树）
- 下方：老师敲黑板汇总（所有 teacher_highlight / common_mistake / teacher_experience）
- 底部按钮：「开始学习」→ 进入学习页

**知识地图结构**：
```text
▼ 雅思阅读考试基本信息
  ├─ 考试时间与题量
  ├─ 阅读题型
  └─ 评分标准

▼ T/F/NG 判断题
  ├─ True 的判断
  ├─ False 的判断
  ├─ Not Given 的判断
  └─ False vs Not Given 的区别
      ├─ ★ 老师重点：最容易混淆的地方
      └─ ⚠ 易错点：同学经常把"没有找到"直接判断为 NG
```

**设计要点**：
- 知识树只展示知识主题，不混入"老师重点""我的笔记"
- 老师重点、易错点作为知识节点下的叶子标记显示
- 点击知识节点 → 展开该节点的教材式内容摘要
- 点击老师重点 → 展开老师的原始强调内容
- 所有内容均可追溯到 Transcript segment

---

### 屏 2 · 课程学习页 `/course/:id/learn`

**目的**：边看视频边学习，随时记录思考，自动绑定时间和知识节点。

**布局（三栏 + 底部）**：
```text
┌──────────────┬──────────────────┬──────────────┐
│              │                  │              │
│  知识树       │     视频播放器    │  知识时间轴   │
│  （左栏）     │     （中栏）      │  （右栏）     │
│              │                  │              │
│ ▼ 阅读基本信息│                  │ 00:00        │
│   ├ 考试时间  │                  │ ● 考试基本信息 │
│   ├ 阅读题型  │                  │              │
│   └ 评分     │                  │ 04:32        │
│              │                  │ ● 阅读题型    │
│ ▼ T/F/NG     │                  │              │
│   ├ True     │                  │ 15:20        │
│   ├ False    │                  │ ★ T/F/NG     │
│   ├ NG       │                  │   ★ 老师重点  │
│   └ F vs NG  │                  │              │
│              │                  │ 💭 我的笔记   │
└──────────────┴──────────────────┴──────────────┘

        ─────────── 视频进度条 ───────────

          [＋ 记录我的想法]  [查看老师原文]
```

**左栏 · 知识树**：
- 多级可展开/折叠
- 当前视频播放位置对应的知识节点高亮
- 点击知识节点 → 视频跳转到该节点开始时间
- 知识节点下显示叶子：★ 老师重点、⚠ 易错点、💭 我的笔记

**中栏 · 视频 + 当前知识**：
- 视频播放器（支持倍速、暂停、拖动）
- 视频下方：当前知识节点的教材式内容
- 「查看老师原文」→ 弹出对应 Transcript 原文
- 「记录我的想法」→ 弹出笔记输入框

**右栏 · 知识时间轴**：
- 垂直时间轴，按时间顺序排列
- 知识节点：●
- 老师重点：★
- 我的笔记：💭
- 点击任意时间轴项 → 视频跳转到对应时间
- 时间轴跟随视频播放位置自动滚动

**底部 · 视频控制**：
- 播放/暂停、进度条、倍速、当前时间/总时长
- 「记录我的想法」按钮（始终可见）
- 「查看老师原文」按钮

**笔记交互流程**：
1. 用户在任意时刻点击「记录我的想法」
2. 弹出输入框，显示当前视频时间和当前知识节点
3. 用户输入内容，点击保存
4. 笔记立即保存（不等待 AI），绑定 video_time 和 current_knowledge_node_id
5. AI 异步判断笔记是否应归属到其他知识节点（若置信度低则保持当前归属）
6. 笔记出现在时间轴和知识树的对应位置

---

### 屏 3 · 复习视图（学习页的复习模式）

**目的**：1-2 分钟快速复习整节课，不需要重新看视频。

**触发方式**：在学习页切换到"复习模式"（或从课程列表直接进入）

**布局**：
- 上方：课程知识地图（同预习页）
- 中间：选中知识节点的详细内容
  - 教材式知识摘要
  - ★ 老师重点
  - ⚠ 易错点
  - 💭 我的笔记（按时间排列）
  - 「查看老师原文」按钮
  - 「跳转视频」按钮（显示对应时间点）
- 下方：课程知识时间轴（同学习页右栏，可点击跳转）

**设计要点**：
- 复习模式下视频播放器默认隐藏（点击"跳转视频"后才展开）
- 用户先看知识地图 → 选择节点 → 看摘要+重点+笔记 → 需要时跳转视频
- 这正是"把书读薄"的核心体验

## 4. 数据模型

> 存储分两层：**静态课程数据**（AI 解析产物，JSON 文件）与**用户状态**（SQLite 数据库）。

### 4.1 静态课程数据（AI 解析产物）

```json
    "created_at": "2026-09-30T10:00:00+08:00"

  "overview": {
    "summary": "教师介绍雅思阅读考试基本形式、题型分布...",
    "estimated_review_minutes": 3

      "id": "kn_001",
      "parent_id": null,

      "start_time": 0,

      "content": "False 和 Not Given 是最容易混淆的地方，很多同学这里会做错。",
      "start_time": 920,

```

**关键设计**：
- `knowledge_nodes` 只存知识主题，不混入老师重点/笔记
- `teacher_insights` 独立存储，通过 `knowledge_node_id` 关联
- `transcript_segments` 是 Whisper JSON 的标准化产物，不修改原始文本
- 所有 AI 生成内容必须携带 `source_segment_ids`
- 时间统一用秒数（float），不存字符串

### 4.2 用户状态（SQLite）

```sql
-- 课程表
CREATE TABLE courses (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  video_path TEXT NOT NULL,
  transcript_path TEXT NOT NULL,
  course_json_path TEXT,
  status TEXT DEFAULT 'pending',  -- pending / processing / ready / failed
  created_at TEXT NOT NULL
);

-- 用户笔记表
CREATE TABLE user_notes (
  id TEXT PRIMARY KEY,
  course_id TEXT NOT NULL,
  knowledge_node_id TEXT,
  video_time REAL NOT NULL,
  content TEXT NOT NULL,
  ai_confidence REAL,
  created_at TEXT NOT NULL,
  FOREIGN KEY (course_id) REFERENCES courses(id)
);

-- AI 解析任务表
CREATE TABLE ai_processing_jobs (
  id TEXT PRIMARY KEY,
  course_id TEXT NOT NULL,
  status TEXT DEFAULT 'pending',  -- pending / processing / completed / failed
  stage TEXT,  -- normalizing / chunking / extracting / merging / summarizing / validating
  progress INTEGER DEFAULT 0,
  error TEXT,
  created_at TEXT NOT NULL,
  completed_at TEXT,
  FOREIGN KEY (course_id) REFERENCES courses(id)
);
```

### 4.3 文件存储结构

```text
coursemap-data/
├── courses/
│   ├── {course_id}/
│   │   ├── course.json          # AI 解析产物
│   │   ├── transcript.json      # 标准化后的 Whisper JSON
│   │   └── video.mp4            # 视频文件（或符号链接）
│   └── ...
└── coursemap.db                 # SQLite 数据库
```

## 6. 核心机制规格

### 6.1 AI Pipeline（7 步）

```text
Whisper JSON
     ↓
① Transcript Normalization（代码，不用 AI）
     ↓
② Semantic Chunking（AI）
     ↓
③ Knowledge Extraction（AI，按 chunk 并行）
     ↓
④ Teacher Insight Extraction（AI，与 ③ 并行）
     ↓
⑤ Knowledge Tree Merge（AI）
     ↓
⑥ Knowledge Summary（AI）
     ↓
⑦ Source Validation（AI）
     ↓
course.json
```

**各步骤规格**：

| 步骤 | 输入 | 输出 | 是否用 AI | 说明 |
| --- | --- | --- | --- | --- |
| ① Normalization | Whisper JSON | 标准化 transcript_segments | 否 | 统一字段、去空、合并短 segment、分配稳定 ID |
| ② Chunking | transcript_segments | chunks[] | 是 | 按语义切分，每 chunk 一个 topic |
| ③ Knowledge Extraction | chunk | knowledge_nodes[] | 是 | 提取知识主题、summary、source_segment_ids |
| ④ Teacher Insight | chunk | teacher_insights[] | 是 | 识别老师明确强调的内容，与 ③ 并行 |
| ⑤ Tree Merge | 所有 chunks 的 nodes | 合并后的知识树 | 是 | 去重、合并、建立父子关系 |
| ⑥ Summary | 知识树 | overview + 各节点 summary | 是 | 生成课程概述和节点摘要 |
| ⑦ Validation | AI 生成内容 | PASS / NEED_REVIEW | 是 | 检查每条 claim 是否有 source 支持 |

**AI 安全规则**：
- 所有 AI 输出必须 JSON Schema 校验
- 不允许补充 Transcript 中没有的信息
- 不允许修改教师原意
- 无法确定来源时标记 `needs_review`，不编造 `source_segment_ids`
- 知识树只存知识主题，不存"老师重点""我的笔记"

### 6.2 笔记自动归类

```text
用户点击保存
     ↓
立即写入 SQLite（course_id, knowledge_node_id, video_time, content）
     ↓
异步调用 AI 归类
     ↓
AI 返回 { knowledge_node_id, confidence }
     ↓
if confidence > 0.85:
    自动更新 knowledge_node_id
elif 0.6 < confidence <= 0.85:
    标记为"建议归类"，等待用户确认
else:
    保持当前归属
```

**AI 归类输入**：
- 用户笔记内容
- 当前视频时间
- 当前 Transcript 上下文
- 课程知识树结构

**规则**：
- 优先使用当前视频时间附近的知识节点
- 其次根据语义匹配
- 不允许创建新知识节点
- 不修改用户原始笔记

### 6.3 时间轴生成

时间轴不是 AI 生成的，而是程序根据以下数据自动投影：

```text
Knowledge Node (start_time) → ●
Teacher Highlight (start_time) → ★
User Note (video_time) → 💭
```

按时间排序，渲染为垂直时间轴。点击任一项 → 视频跳转到对应时间。

## 8. 边界条件与异常状态

### 8.1 数据层

| # | 情形 | 处理 |
| --- | --- | --- |
| 8.1.1 | Whisper JSON 格式不统一 | Normalization 步骤做容错，支持多种常见格式 |
| 8.1.2 | Transcript 中有空 segment | 自动过滤 |
| 8.1.3 | Transcript 中有异常短 segment（<1s） | 合并到相邻 segment |
| 8.1.4 | AI 解析失败（API 超时/返回异常） | 标记 failed，支持重试，不丢失已完成的步骤 |
| 8.1.5 | AI 生成的 source_segment_ids 不存在 | Validation 步骤检查，标记 needs_review |
| 8.1.6 | 视频文件不存在或路径错误 | 课程列表标红，提示重新关联 |

### 8.2 用户行为层

| # | 情形 | 处理 |
| --- | --- | --- |
| 8.2.1 | 解析过程中关闭页面 | 后台继续执行，重新打开时显示最新状态 |
| 8.2.2 | 笔记保存时网络断开（LLM API 不可用） | 笔记立即保存本地，AI 归类延迟到网络恢复 |
| 8.2.3 | 视频播放到一半切换课程 | 保存当前播放位置，下次进入恢复 |
| 8.2.4 | 知识树为空（AI 未提取到任何知识点） | 显示"AI 未能提取知识结构"，建议重新解析 |

### 8.3 系统层

| # | 情形 | 处理 |
| --- | --- | --- |
| 8.3.1 | SQLite 数据库损坏 | 启动时检查，损坏则重建（用户数据丢失，但课程 JSON 仍在） |
| 8.3.2 | 磁盘空间不足 | 导入时检查，不足时提示 |
| 8.3.3 | LLM API 配额用完 | 提示用户，暂停解析，支持恢复 |

## 9. 成功指标

> 本产品为个人工具，不以用户量/留存率为指标。核心衡量：**三个关键行为是否真的发生**。

### 9.1 北极星

**复习频率** = 使用复习视图的次数 / 学习次数。

- 如果用户学完课后真的回来用复习视图（而不是重新看视频），说明"把书读薄"成立。
- 目标：第 2 周起，复习频率 > 50%。

### 9.2 过程指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 笔记数量 | 每节课平均笔记数 | 观察用户是否真的在"产生思考" |
| 溯源点击率 | 点击"查看原文"/"跳转视频"的次数 | 观察用户是否真的在用溯源功能 |
| 解析成功率 | AI 解析成功 / 总解析次数 | 观察 Pipeline 稳定性 |
| 预习时长 | 预习页停留时间 | 观察是否在 2-5 分钟范围内 |

### 9.3 反指标

- ❌ 不使用"重新看完整视频"作为成功证据
- ❌ 不以"AI 总结看起来很长"为荣

## 12. 已知风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **AI 解析质量** | 知识树不准确、老师重点遗漏 | Validation 步骤 + 用户可手动编辑（N-02） |
| **LLM API 成本** | 80 节课解析可能产生较高费用 | 先用 1 节课测试，确认质量后再批量 |
| **视频文件格式** | 不同课程视频格式可能不同 | 前端 `<video>` 支持 MP4/WebM，其他格式需转码 |
| **Whisper JSON 格式差异** | 不同课程转写格式可能不同 | Normalization 做容错，支持多种格式 |
| **本地文件路径** | 视频移动后路径失效 | 导入时复制/链接到统一数据目录 |
| **交互设计未验证** | ChatGPT 原型不满意，实际交互可能需大幅调整 | Phase 1 先跑通数据流，交互细节后续迭代 |

## 13. 开发阶段

### Phase 1：数据流 + 交互闭环（不接 AI）

**目标**：用人工构造的 course.json 跑通前端交互。

- 导入课程（Whisper JSON + 视频）
- Transcript 标准化
- 人工构造一份 course.json（知识树 + 老师重点 + 时间轴）
- 前端三页面：列表 / 预习 / 学习
- 视频播放 + 知识树联动 + 时间轴联动
- 记录笔记 + 绑定时间
- 查看原文 + 溯源跳转

**验收**：用一份真实课程数据，完成 A1-A13 中除 A2/A9 外的所有验收项。

### Phase 2：AI Pipeline

**目标**：接入 LLM API，自动解析生成 course.json。

- 7 步 Pipeline 实现
- 异步任务 + 进度显示
- JSON Schema 校验
- Validation 步骤

**验收**：AI 解析后的 course.json 可通过人工抽查，知识树基本准确。

### Phase 3：复习视图 + 打磨

**目标**：完成复习模式，打磨交互细节。

- 复习视图实现
- 笔记异步归类
- 交互细节优化（根据用户反馈）

**验收**：完整三阶段闭环跑通。
