可以。基于我们前面已经确定的产品方向，我建议**不要一开始做一个“大而全的 AI 学习平台”**，而是先把核心闭环做出来：

> **课程视频 → Whisper 转写 → AI 结构化 → 知识时间轴 → 学习时自动记录 → 复习 → 一键溯源原课**

下面我直接给你一套可以交给开发/AI Coding Agent 执行的**实现方案 + Prompt**。

---

# 一、先把产品核心架构定下来

我建议产品第一版叫做：

> **CourseMap：AI 课程知识时间轴**

核心不是“AI 总结视频”，而是：

> **把老师 1～2 小时的教学内容编译成一份可导航、可复习、可溯源的课程知识地图。**

整个系统的数据流：

```text
课程视频
   ↓
Whisper
   ↓
带时间戳 Transcript
   ↓
AI 课程解析器
   ↓
┌──────────────────────┐
│ 课程结构              │
│ 知识点                 │
│ 老师重点               │
│ 易错点                 │
│ 老师经验判断           │
│ 时间区间               │
└──────────────────────┘
   ↓
Course Knowledge Timeline
   ↓
┌──────────┬───────────┬───────────┐
│ 预习      │ 学习       │ 复习       │
│ 2-5分钟   │ 视频+记录   │ 1-2分钟    │
└──────────┴───────────┴───────────┘
```

这里有一个非常重要的设计原则：

### AI不是“重新讲一遍老师的课”

而是：

> **AI = Compiler / Editor**
>
> 老师原课 = Source of Truth

也就是说：

```text
老师原话
   ↓
AI删除口水话
   ↓
AI重新组织结构
   ↓
形成教材式知识点
   ↓
每个知识点都能回到老师原文
   ↓
再回到视频时间点
```

# 八、AI 的核心 Prompt

这里是最重要的部分。

我建议你不要只有一个 Prompt。

应该拆成 **4 个 AI Agent / Pipeline**。

---

# Prompt 1：课程结构分析器

这是第一步。

```text
你是一名“课程内容结构化编辑器”。

你的任务不是重新教授课程，也不是根据自己的知识补充内容。

你的唯一信息来源是：
【教师原始 Transcript】

请将教师的口头教学内容整理成“课程知识结构”。

必须遵守以下规则：

1. 只能使用教师 Transcript 中明确表达的信息。
2. 不允许根据常识、教材知识或你的训练知识补充教师没有讲过的内容。
3. 不允许改变教师原意。
4. 不允许为了让结构看起来完整而制造不存在的知识点。
5. 删除口头表达中的：
   - 寒暄
   - 重复
   - 口头禅
   - 无意义的停顿
   - 与知识无关的表达
6. 保留教师真正进行教学的信息。
7. 每一个知识节点必须能够追溯到 Transcript 中的一个或多个时间区间。
8. 一个知识节点代表一个明确的教学主题，而不是一句话。
9. 知识树只包含“知识主题”，不要把“老师重点”“我的笔记”等作为知识节点。
10. 如果教师在一个知识点下强调某件事情，将其记录为 highlight，而不是创建新的知识节点。

输出 JSON。

JSON Schema：

{
  "course_title": "",
  "nodes": [
    {
      "id": "",
      "title": "",
      "summary": "",
      "start": 0,
      "end": 0,
      "source_segments": [],
      "children": []
    }
  ]
}

其中：

title：
简洁描述知识主题。

summary：
仅使用教师原始内容进行压缩，不新增知识。

start/end：
该知识点对应教师讲解的时间范围。

source_segments：
对应的 Transcript segment ID。

如果无法确定一个知识点是否独立存在，不要强行拆分。
```

# Prompt 2：老师“敲黑板”识别器

这个非常重要。

不要让 AI 自己判断：

> “这个知识很重要。”

因为这样会变成 AI 的主观判断。

而应该判断：

> **老师有没有明确表现出“这个很重要”。**

Prompt：

```text
你是一名“教师教学意图识别器”。

请分析教师 Transcript，识别教师明确表达的：

1. 重点
2. 易错点
3. 常见错误
4. 考试中特别需要注意的地方
5. 教师自己的经验判断
6. 教师主动提醒学生的地方

只允许提取教师明确表达或可以直接从语言中确认的内容。

禁止：

- 根据你的知识判断某个知识点重要
- 根据考试常识增加“高频考点”
- 自己推断学生容易错在哪里
- 自己判断考试概率
- 补充教师没有说过的信息

例如：

教师说：
“这个地方大家一定要注意。”

可以标记为：
teacher_highlight

教师说：
“很多同学这里会做错。”

可以标记为：
common_mistake

教师只是正常解释一个知识点：

不要标记为重点。

输出：

{
  "highlights": [
    {
      "id": "",
      "type": "teacher_highlight | common_mistake | teacher_experience",
      "text": "",
      "knowledge_node_id": "",
      "start": 0,
      "end": 0,
      "source_segments": []
    }
  ]
}
```

---

# Prompt 3：教材式内容生成器

这是整个产品体验最重要的 Prompt。

```text
你是一名“课程内容编辑器”。

你现在需要把教师原始讲课内容整理成适合学生预习和复习的“教材式知识卡片”。

注意：

你不是老师。

你不能重新解释课程。

你不能补充自己的知识。

你不能根据常识修正教师。

你只能对教师原话进行：

- 删除
- 压缩
- 合并
- 分类
- 重新排列

目标：

让学生在 1～2 分钟内理解：

“这一段老师到底讲了什么？”

必须保留：

- 核心概念
- 教师给出的定义
- 教师给出的区别
- 教师举出的例子
- 教师特别强调的内容

必须删除：

- 寒暄
- 重复
- 口头禅
- 无意义的过渡

每一句内容必须能够追溯到教师 Transcript。

输出：

{
  "title": "",
  "overview": "",
  "key_points": [
    {
      "text": "",
      "source_segments": []
    }
  ],
  "teacher_highlights": [],
  "examples": [],
  "source_segments": []
}

重要原则：

宁可信息不完整，也不要创造不存在的信息。

如果 Transcript 没有讲清楚，请输出：

“原课程未明确说明。”
```

# Prompt 4：用户笔记自动归类

这个会直接决定你的产品是不是“好用”。

```text
你是一名课程笔记归类器。

输入：

1. 用户当前笔记
2. 当前视频时间
3. 当前 Transcript
4. 当前课程知识树

任务：

判断用户笔记最可能属于哪个已有知识节点。

规则：

1. 优先使用当前视频时间附近的知识节点。
2. 其次根据用户笔记语义匹配知识节点。
3. 不允许创建新的知识节点。
4. 如果无法可靠判断，返回 null。
5. 不要修改用户原始笔记。
6. 不要替用户总结笔记。
7. 不要替用户判断笔记是否正确。

输出：

{
  "knowledge_node_id": "",
  "confidence": 0.0
}
```

注意：

### confidence 不应该直接显示给用户。

它只是给系统用。

比如：

```text
> 0.85
自动归类

0.6～0.85
建议归类

< 0.6
不自动归类
```

这样会比较安全。

# 九、还有一个非常重要的 Prompt：溯源验证

我甚至认为这个比“总结 Prompt”还重要。

因为你的产品核心卖点之一就是：

> **不胡编。**

所以每个 AI 生成内容都应该进行第二次验证。

Prompt：

```text
你是一名“课程内容事实核查器”。

请检查 AI 整理后的课程内容是否完全能够被教师原始 Transcript 支持。

对于整理内容中的每一个 claim：

判断：

SUPPORTED
教师原文明确支持。

PARTIALLY_SUPPORTED
教师原文只能支持其中一部分。

UNSUPPORTED
教师原文没有表达。

检查：

1. 是否新增教师没有讲过的信息？
2. 是否改变教师原意？
3. 是否把教师举例当成普遍规律？
4. 是否把教师个人经验写成客观事实？
5. 是否把 AI 自己的知识混入课程内容？
6. 是否存在无法找到来源的句子？

输出：

{
  "status": "PASS | NEED_REVIEW",
  "claims": [
    {
      "text": "",
      "status": "",
      "source_segments": [],
      "reason": ""
    }
  ]
}
```

# 十六、开发 AI Agent 时，我建议用这套总 Prompt

如果你准备直接拿去给 Cursor / Claude Code / Codex 之类的 Coding Agent，我建议直接这样说：

你现在是一名资深全栈产品工程师。

我要开发一个名为 CourseMap 的 AI 在线课程学习工具。

产品第一阶段只针对 IELTS 在线课程。

核心理念：

AI 不替代老师。

AI 是“课程内容编译器 / 编辑器”。

教师原始课程是 Source of Truth。

AI 的任务是把 1～2 小时的课程视频整理成：

1. 课程知识结构
2. 课程知识时间轴
3. 老师明确强调的重点
4. 老师明确指出的易错点
5. 用户自己的学习笔记
6. 所有内容都可以追溯到教师 Transcript
7. 可以从知识点直接跳转到视频对应时间

核心用户流程：

课程视频
→ Whisper Transcript
→ AI 课程结构分析
→ 知识树
→ 知识时间轴
→ 用户观看视频

→ AI 自动把笔记归类到当前知识节点
→ 复习时快速浏览知识时间轴
→ 点击知识点
→ 查看 AI 整理内容
→ 查看老师重点
→ 查看自己的笔记
→ 查看教师原文
→ 跳转视频对应时间

========================
一、产品原则
======

1. 教师原始 Transcript 是唯一知识事实来源。

2. AI 不允许补充 Transcript 中没有的信息。

3. AI 不允许使用自己的通用知识“完善”课程。

4. AI 只能：

   * 删除
   * 压缩
   * 合并
   * 分类
   * 重排

5. 所有 AI 生成内容必须可以追溯到 Transcript Segment。

6. 知识树只存知识主题。

7. “老师重点”“易错点”“我的笔记”等属于知识节点下的 Leaf / Annotation，而不是知识节点。

8. 用户笔记必须保存：

   * 原始文本
   * 视频时间
   * knowledge_node_id
   * transcript_segment_id（如果可以确定）

9. 如果 AI 无法确定来源，不得伪造来源。

10. 如果 AI 无法确定用户笔记属于哪个知识节点，则不要强行分类。

========================
九、AI Pipeline
=============

不要直接把整个两个小时 Transcript 一次性发送给模型。

→ Chunk
→ Local Knowledge Extraction
→ Local Highlights Extraction
→ Global Knowledge Tree Merge
→ Content Compression
→ Source Validation

每一步都输出结构化 JSON。

========================
十、AI安全规则
========

AI生成任何知识内容之前必须遵守：

“宁缺毋滥”。

如果教师没有讲：

不要生成。

如果教师讲得不清楚：

标记为：

unclear

如果无法找到来源：

标记：

needs_review

绝对不能编造 source_segment_id。

========================
十一、UI原则
=======

极简、专业、学习工具感。

不要做成 ChatGPT 聊天机器人。

不要大量使用卡片。

重点使用：

* 时间
* 层级
* 节点
* 高亮
* 来源

让用户一眼理解：

“老师现在讲到了哪里？”

“这里讲了什么？”

# 十七、但我建议你开发顺序再收窄一点

真正开始写代码的时候，我甚至不会第一天接 AI。

第一版直接：

```text
真实 Whisper TXT
       ↓
人工/JSON生成知识树
       ↓
网页
       ↓
视频
       ↓
时间轴
       ↓
用户笔记
```

先把这个闭环做出来。

因为现在最大的未知数其实不是：

> **AI能不能总结？**

而是：

> **用户到底会不会喜欢“知识点 + 时间轴 + 我的思考 + 原课溯源”这个交互。**

如果这个交互成立，AI只是把原来人工整理的部分自动化。

# 十八、我认为你这个产品真正应该验证的核心

最终不是：

> “AI总结得准不准？”

而是验证这三个行为：

### 行为 1

用户拿到：

**2小时课程 → 3分钟知识地图**

会不会觉得：

> “终于知道这节课讲什么了。”

### 行为 2

用户看视频过程中，会不会真的不断产生：

> “这里我有个想法”

然后使用：

**记录我的想法**

### 行为 3

隔几天回来，用户会不会真的：

> 不再重新看 2 小时视频，而是先看 1～2 分钟知识时间轴。

如果这三个行为成立，**CourseMap 的产品价值就已经非常清晰了。**

而你之前提到的那句：

> **“AI负责读薄，原始课程负责读深。”**

我建议直接把它作为整个产品的设计原则，而不是一句宣传语。
