# 四、Knowledge Node

例如：

```json
{
  "id": "knowledge_001",
  "parent_id": null,

  "title": "雅思阅读考试基本信息",

  "summary": "教师介绍雅思阅读考试的基本形式、时间和题量。",

  "start_time": 0,
  "end_time": 420,

  "children": [
    {
      "id": "knowledge_001_001",
      "title": "考试时间与题量",
      "summary": "...",
      "start_time": 32,
      "end_time": 120,
      "source_segment_ids": [
        "seg_12",
        "seg_13",
        "seg_14"
      ]
    }
  ],

  "source_segment_ids": [
    "seg_12",
    "seg_13",
    "seg_14"
  ]
}
```

这里有一个关键点：

### 不要让 AI 自己保存原文。

只保存：

```text
source_segment_ids
```

真正的原文永远从：

```text
transcript_segments
```

查询。

这样可以避免：

> AI 修改了原文 → 数据库里面出现两个版本。

# 五、Teacher Insight

type 第一版只需要：

```text

teacher_experience
```

暂时**不要做**：

```text

AI_judged_important
likely_tested
```

因为这些已经开始进入 AI 自己判断的领域了。

你的产品核心原则还是：

> **老师说过什么，就整理什么。**

# 七、① Transcript Normalization

这一步不要用 AI。

直接代码处理。

例如：

```text
Whisper JSON
    ↓
统一字段
    ↓
segment_id
start
end
text
```

变成：

```json
{
  "id": "seg_000123",
  "start": 1523.2,
  "end": 1534.8,
  "text": "..."
}
```

然后做：

* 去除空 segment
* 合并异常短 segment
* 修复明显格式问题
* 保持原始 timestamp
* 给每个 segment 一个稳定 ID

**这一层尽量 100% deterministic。**

---

# 八、② Semantic Chunking

这里才第一次进入 AI。

但不要让 AI 直接生成最终知识树。

先问它：

> “老师现在这一段在讲什么？”

例如：

```text
00:00 - 04:32
课程介绍

04:32 - 08:15
考试基本信息

08:15 - 15:20
阅读题型

15:20 - 24:10
T/F/NG
```

输出：

```json
[
  {
    "chunk_id": "chunk_01",
    "start": 0,
    "end": 272,
    "topic": "课程介绍"
  },
  {
    "chunk_id": "chunk_02",
    "start": 272,
    "end": 495,
    "topic": "考试基本信息"
  }
]
```

这样后面 AI 的工作量会小很多。

# 九、③ Knowledge Extraction

对每个 chunk 进行：

```text
Chunk
 ↓
知识点
 ↓
知识点之间的层级
 ↓
summary
 ↓
source_segment_ids
```

这里最重要的 Prompt 我建议改成：

```text
你是课程内容结构化编辑器。

输入是教师真实授课 Transcript。

你的任务是识别教师在这一段实际讲授的知识主题。

不要根据你的知识补充课程内容。

只允许使用 Transcript 中明确表达的信息。

你可以：

- 删除口头重复
- 压缩表达
- 合并相同内容
- 提取知识主题
- 调整结构

你不可以：

- 补充教师没有讲过的知识
- 修改教师原意
- 根据常识增加知识点
- 判断教师没有表达的“考试重点”
- 创建 Transcript 中不存在的结论

每个知识点必须返回 source_segment_ids。

如果内容不足以形成独立知识点，就不要创建。

输出严格 JSON。
```

# 十、④ Teacher Insight Extraction

这个可以和 Knowledge Extraction **并行执行**。

也就是说：

```text
                 ┌→ Knowledge Extraction
Transcript Chunk ┤
                 └→ Teacher Insight Extraction
```

而不是：

```text
Knowledge Extraction
       ↓
Teacher Insight
```

这样更容易控制 AI 的偏差。

# 十一、⑤ Knowledge Tree Merge

这一层很重要。

假设 AI 分块之后得到：

```text
Chunk 1
  T/F/NG

Chunk 2
  True / False / Not Given

Chunk 3
  False 和 NG 区别

Chunk 4
  T/F/NG 常见错误
```

现在需要一个：

> **Tree Builder**

把它合并：

```text
T/F/NG
│
├── True
├── False
├── Not Given
│
└── False vs Not Given
```

这一步的任务不是总结。

而是：

> **去重 + 合并 + 建立父子关系。**

## 二十二、现在你的产品其实已经到了一个很好的节点

从技术角度看，之前最大的链路：

```text
视频 → 语音 → 文字 → 时间戳
```

你已经解决了。

所以现在真正值得投入精力的是：

```text
                  你现在的位置
                       ↓
视频 → Whisper → JSON → 【AI理解】
                          ↓
                    【知识结构】
                          ↓
                 【知识时间轴】
                          ↓
                【学习过程中的笔记】
                          ↓
                    【复习】
                          ↓
                    【原课溯源】
```

而且这里有一个很重要的架构结论：

> **不要让 AI 控制整个产品。**

AI 只负责：

**理解内容。**

程序负责：

**时间、数据、关联、播放、交互。**

这样你的系统会稳定很多。

最终你真正拥有的核心数据不是一份 AI Summary，而是一个：

```text
Course
 ├── Transcript
 ├── Knowledge Graph
 ├── Timeline
 ├── Teacher Insights
 ├── User Notes
 └── Source Mapping
```

这才是以后可以不断扩展的产品底座。

下一步最适合直接进入**Phase 1：拿你现有的一门真实 IELTS 课程 JSON，定义完整的 Course JSON Schema + AI 输出 Schema，然后做前端页面**。这样不会再停留在方案层，而是可以直接开始写第一版。
